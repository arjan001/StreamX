## 1. PROJECT OVERVIEW

### 1.1 What is Streamix?
Streamix is a cross-platform IPTV media player application built with a single React frontend packaged for multiple platforms:
- **Web** (React + Vite)
- **Android** (Capacitor shell with libVLC native player) - Phone, Tablet, Android TV
- **iOS** (Capacitor)
- **Samsung Tizen** TV (.wgt package)
- **LG webOS** TV (.ipk package)

The app contains **no built-in content**. Users add their own sources (Xtream servers, M3U playlists, Stalker portals, or single stream links), and the app plays what those sources provide.

### 1.2 Technology Stack
- **Frontend:** React with TypeScript, Vite build tool
- **State Management:** TanStack React Query
- **Routing:** React Router DOM
- **Mobile Shell:** Capacitor (bridges web app to native Android/iOS)
- **Android Player:** libVLC native playback engine
- **Package Manager:** pnpm (workspaces)
- **Node.js:** >= 22
- **Build Tool:** Gradle (Android), Vite (Web)

### 1.3 Repository Structure
```
apps/
  web/              → React app: all screens, player, remote handling
  mobile/           → Capacitor shell: Android (libVLC) and iOS
  tizen/            → Samsung TV package
  webos/            → LG TV package
  server/           → Publisher's server (Node, Postgres)
packages/
  core-xtream/      → Xtream-style API client
  core-m3u/         → M3U/M3U8 parser
  core-stalker/     → Stalker/MAC portal client
  core-store/       → On-device catalogue: indexes, search, guide
brand/              → Logo and brand assets
brand.config.json   → Name, colors, IDs, publisher info
scripts/            → Build helpers, brand application
docs/               → GitHub Pages documentation site
internal-docs/      → Technical documentation
legal/              → Terms, Privacy, Copyright
.github/workflows/  → CI/CD pipelines
```

## 3. ANDROID APK BUILD SYSTEM

### 3.1 Three APK Variants
The build system produces **3 separate APK variants** via ABI splitting in `apps/mobile/android/app/build.gradle`:

| Variant | File Name | Target Devices | Size (approx) |
|---------|-----------|----------------|---------------|
| **ARM64** | `app-arm64-v8a-debug.apk` | Modern phones & TV boxes (recommended) | ~51 MB |
| **ARMv7** | `app-armeabi-v7a-debug.apk` | Older devices & legacy TV boxes | ~46 MB |
| **Universal** | `app-universal-debug.apk` | All devices (larger file) | ~91 MB |

**Why 3 variants?** libVLC ships native decoder libraries per architecture. Splitting reduces download size significantly. The universal APK contains both ARM64 and ARMv7 decoders combined.

### 3.2 Build Configuration
- **NDK ABI Filters:** `arm64-v8a`, `armeabi-v7a` (x86 intentionally excluded to save ~106MB)
- **Debug vs Release:** Debug APKs use a shared debug key; Release requires `~/.streamix-signing/keystore.properties`
- **Application ID Suffix:** Debug builds use `.debug` suffix, so debug and release can coexist on the same device
- **Minify/Shrink:** Disabled for release (Capacitor and libVLC JNI break with R8 shrinking)

### 3.3 Build Commands
```bash
pnpm --filter @iptv/mobile apk        # Debug APK (3 variants)
pnpm --filter @iptv/mobile bundle     # Release AAB (Google Play)
pnpm --filter @iptv/mobile build:android  # Both
```

## 4. GITHUB ACTIONS & CI/CD

### 4.1 Workflows Overview

#### A. `build-android-apk.yml` (Main Build Pipeline)
**Triggers:** Push to `main`, PRs to `main`, manual dispatch

**Jobs:**
1. **test** - Runs unit tests (`pnpm test`)
2. **typecheck** - TypeScript type checking (`pnpm typecheck`)
3. **build-apk** - Builds all 3 APK variants
   - Installs pnpm, Node 22, JDK 21
   - Builds web app (`pnpm build`)
   - Syncs to Capacitor
   - Runs `./gradlew assembleDebug`
   - **Uploads each APK as a separate artifact** (arm64, armeabi-v7a, universal)
   - Generates timestamp-based version tag
   - Creates git tag

4. **create-release** - Creates GitHub Release
   - Downloads APK artifacts
   - Generates SHA256 checksums
   - Uploads APKs as release assets with separate download links
   - Release notes describe each APK variant

**Key Finding:** APKs are uploaded as **separate artifacts**, NOT zipped together. Each APK is individually downloadable from GitHub Actions artifacts and GitHub Releases.

#### B. `deploy-docs.yml` (GitHub Pages Deployment)
**Triggers:** Push to `main`, manual dispatch

**Process:**
1. Downloads APK artifacts from build-apk job
2. Copies `docs/`, `internal-docs/`, `legal/` to site directory
3. **Copies all APKs individually to the site root** with clear names
4. Updates version placeholder in `index.html`
5. Deploys to GitHub Pages

**Key Finding:** The GitHub Pages site serves APKs as **direct download links**, not as a zip file. Each APK has its own `<a href="app-arm64-v8a-debug.apk" download>` link.

#### C. `release.yml` (Tag-based Release)
**Triggers:** Git tags matching `v*`

**Process:**
- Runs tests and typecheck
- Builds web app and Android APKs
- Creates GitHub Release with APKs and checksums

#### D. `ios.yml`
- iOS build configuration (requires Mac environment)

## 5. APP UI FLOW ANALYSIS

### 5.1 Current Flow (First Launch)

```
App Launch
    ↓
Boot Sequence (main.tsx)
    ├─ Hydrate storage (kv, providers, prefs, skin)
    ├─ Detect device type (TV vs phone)
    ├─ Load local catalogue from IndexedDB
    ├─ Restore session
    └─ Render React app
    ↓
Splash Screen (HTML/CSS, id="splash")
    ↓ (removed after first paint, ~2 frames)
    ↓
Gate Component (main.tsx)
    ↓
doorOpen() check (lib/firstRun.ts)
    ↓
    ├─ TRUE (first time, no session) → Welcome Overlay
    │   ↓
    │   Welcome.tsx shows over Home page
    │   ↓
    │   "Welcome to Streamix" + "Add a source to get started"
    │   ↓
    │   AddSource component (AddSource.tsx)
    │   ↓
    │   Source Type Picker:
    │   ├─ Server (Xtream) → SignInFields form
    │   ├─ Playlist (M3U) → PlaylistForm
    │   ├─ Stream Link → StreamForm
    │   └─ Stalker Portal → StalkerForm
    │   ↓
    │   For Xtream: SignInFields.tsx
    │   ├─ Server address field (http://host:port)
    │   ├─ Username field
    │   └─ Password field
    │   ↓
    │   "Add server" button → signIn() → catalogue download
    │   ↓
    │   "Source added" → Choice: "Start watching" or "Personalise"
    │
    └─ FALSE (returning user) → Direct to Home/Live
        ↓
        Main app with Chrome (header + tabs)
```

### 5.2 Key Components

#### Welcome.tsx (First-Run Overlay)
- Blocking overlay over the Home page
- Shows `AddSource` component for source type selection
- After source added, shows "Start watching" / "Personalise" choice
- Controlled by `doorOpen()` in `lib/firstRun.ts`
- Durable: once answered, stored in `kv` (IndexedDB)

#### AddSource.tsx (Source Type Picker)
- Shows 4 source types: Xtream Server, M3U Playlist, Stream Link, Stalker Portal
- Each type has its own form
- For Xtream, delegates to `SignInFields` component

#### SignInFields.tsx (Xtream Login Form)
- **3 input fields:**
  1. Server address (`http://host:port`)
  2. Username (or full get.php link)
  3. Password
- Validates credentials via `parseLineCredentials()`
- Submits via `signIn()` in `lib/session.ts`
- On success: stores session digest, starts catalogue download

#### Chrome.tsx (App Shell)
- Header with: Logo/Wordmark, navigation tabs, settings, adult icon
- Tab bar: Home, Live, Sports, Guide, Catchup, Movies, Series, Search
- Adult bunny icon in header (links to `/adult`)

## 9. SESSION & AUTHENTICATION FLOW

### 9.1 How Authentication Works

1. **signIn()** in `lib/session.ts`:
   - Accepts username, password, and optional server URL
   - Parses credentials (supports `get.php?username=...&password=...` format)
   - Calls `signInXtream()` to authenticate against the panel
   - On success: stores SHA-256 digest of credentials as session
   - Triggers catalogue download

2. **Session Storage:**
   - Key: `iptv.session.v1`
   - Value: `{ account: "<sha256-digest>", at: <timestamp> }`
   - Stored in `kv` (IndexedDB on web, app-private storage on native)

3. **First-Run Gate:**
   - Key: `iptv.onboarded.v2`
   - `doorOpen()` returns true if no onboarding marker AND no session
   - Once user adds a source, `markOnboarded('welcome')` is called
   - Door only reopens if last source is removed (`reopenDoor()`)

### 9.2 For Hardcoded Server Implementation

To implement the hardcoded server URL (`http://line.istreamix.com/`):

1. The `signIn()` function already accepts an optional `url` parameter
2. The `SignInFields` component currently requires the user to type the server URL
3. Modification needed:
   - Add a `defaultServer` prop to `SignInFields`
   - When set, hide the server address field
   - Pass the hardcoded URL to `signIn()` automatically
   - Or create a wrapper component that pre-fills the server URL
